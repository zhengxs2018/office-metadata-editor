```mermaid
    F-->>R: docProps/core.xml + app.xml
    R-->>I: 统一元数据模型
    I-->>P: DocumentMetadata
    P->>S: 写入上下文
    S-->>P: 渲染字段表单

    U->>P: 修改字段
    P->>S: 更新草稿态
    Note over S: 脏标记 + 撤销栈

    U->>P: 保存
    P->>I: save_docx_metadata_to_source
```

```mermaid
    subgraph Report["反馈"]
        H1 --> R1["逐条结果"]
        H2 --> R1
        H3 --> R1
        H4 --> R1
        R1 --> R2["成功 / 失败分组"]
        R2 --> R3["失败项可重试"]
    end

    style Prepare fill:#0c4a6e,stroke:#0ea5e9,color:#fff
    style Execute fill:#7c2d12,stroke:#ea580c,color:#fff
    style Report fill:#14532d,stroke:#22c55e,color:#fff
```

批量命令按格式分派而非统一入口，因为四种格式的写回语义差异较大（OOXML 改 ZIP 条目、PDF 改 Info 字典与 XMP、DOC 改 OLE 流），强行抽象会让错误处理变得含糊。

批量操作**逐条返回结果**而非整体成功 / 失败，部分文件被占用或只读时，其余文件仍应正常处理。

## 长任务与中断

`create_automation_request` / `cancel_automation_request` / `finish_automation_request` / `get_automation_request_status` 四个命令构成可中断的长任务协议：

```mermaid
sequenceDiagram
    autonumber
    participant P as 页面
    participant I as IPC
    participant R as 任务管理

    P->>I: create_automation_request
    I->>R: 登记任务
    R-->>P: requestId

    loop 轮询进度
        P->>I: get_automation_request_status(requestId)
        I->>R: 查询
        R-->>P: 进度 / 状态
    end

    alt 用户取消
        P->>I: cancel_automation_request(requestId)
        I->>R: 置取消标记
        R-->>P: 已取消
    else 正常完成
        P->>I: finish_automation_request(requestId)
        R-->>P: 完成
    end
```

批量处理数百个文件时，用户必须能随时中止，且需要看到进度而非无反馈等待。

## 错误处理约定

所有命令返回 `Result<T, String>`，错误消息须包含**发生了什么 + 怎么解决**，而非裸堆栈：

| 场景 | 消息形态 |
|------|---------|
| 文件被占用 | 说明文件被其他程序打开，建议关闭后重试 |
| 只读文件 | 说明权限不足，建议改用「另存为」 |
| 格式损坏 | 说明无法解析，建议检查文件完整性 |
| 加密文档 | 说明受密码保护，建议先解除保护 |

前端所有 `await` 必须置于 `try/catch` 或 `.catch` 内，禁止裸 `await` 导致未处理的 rejection。
