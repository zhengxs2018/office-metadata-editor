## 首页顶部还原（再次改造）

用户反馈：用 PageLayout 后首页头部变得太小（title 16px），且紧贴顶部 32px chrome 安全区易导致拖拽区域失效；主题切换也盖住 Windows 关闭按钮。

实施：

- **目录迁移**：`src/pages/home-page.tsx` → `src/pages/home-page/index.tsx`（App.tsx 的 `./pages/home-page` 路径不变，Vite/TS 自动解析 `index.tsx`）
- **回到 BlankLayout**：首页特殊（不要 AppShell 的 32px fixed titlebar），用 `BlankLayout`（不传 `header` prop，BlankLayout 自动渲染 `ChromeWindowToolbar` 作为 32px 顶部纯拖拽层）
- **header 自渲染**：在 children 内用 `<header>` 标签，**不再依赖 PageLayout 的 header/actions 槽位**
  - 标题还原为 `text-2xl font-semibold tracking-tight`（之前版本样式），副标题 `text-sm text-muted-foreground`
  - 主题切换保留在 header 右侧 `actions` 位置
- **关键 paddingTop `pt-10` (40px)**：让 header 内容顶部距 main top 40px —— 在 ChromeWindowToolbar (0-32px) 下方 8px，**避免拖拽区域被 header 内容"挤掉"**
- **背景自然融入**：首页不依赖 AppShell 的 `bg-parchment/80 + hairline-b`，header 自身透明 + children 容器 `bg-background`，**与内容区同色**，无视觉分割

- 主题切换不再用 `app-no-drag`：因为 header 整个不在 ChromeWindowToolbar 区域，**没必要标记**
- **不要在 header 上加 `data-tauri-drag-region`**：BlankLayout 已渲染 `ChromeWindowToolbar` 处理顶部 32px 拖拽，header 在 32px 以下再加 drag 是冗余

**判据一句话**：首页 = BlankLayout + 自渲染 header，header 内容从 main top 40px 开始，与 chrome bar 有 8px 视觉间距。

## 风险报告 Bug 修复

- **Bug：3 家公司时 hero 标题只显示 2 家**：原因是 hero 用了 `involvedCompanyIds`（只含 findings 里出现过的公司）。Rust 端 `compare_files` 只对 company_a × others 做两两对比，当 company_a=A、其他=B/C 时，findings 只涉及 {A,B} 或 {A,C}，从未共同涉及 B+C 的 finding，所以 `involvedCompanyIds` 可能缺第三家。修复：hero 改用 `companySnapshots`（全部公司），未涉及的公司 chip 加 `opacity-50` + `title="未涉及风险"`。
- **Bug：2 家公司对阵图卡片上下堆叠**：原用 `flex flex-nowrap` + `min-w-`，flex item 没有 max-width 限制，被内容自然撑宽；sm+ `flex-wrap` 让每张卡撑满一行。修复：1/2/3 家改用 `grid` 严格分配列数（`grid-cols-1` / `sm:grid-cols-2` / `sm:grid-cols-3`），**只有 ≥4 家才走 ScrollArea 横滚**。`CompanyBattleRow` props 改 `(snapshots, involvedIds)`，不再重复计算。
- hero 标题 `cn(... !isInvolved && findings.length > 0 && "opacity-50")`：仅当存在 findings 但该公司未卷入时降透明度，避免"无风险时全部 50%"误导。
