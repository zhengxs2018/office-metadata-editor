## 增量修复：对比页 UX 第二轮

### 1. 崩溃根因：LoadedDocument.fileName = undefined
- `metadata-context` 中 `LoadedDocument` 类型只有 `metadata: NormalizedMetadata`（其中含 `fileName`），不存在顶层 `.fileName`。
- `compare-page/index.tsx` 和 `company-slot.tsx` 直接读 `doc.fileName` → undefined → `compare-matching.ts` `extractExtension` 调 `undefined.match(...)` 崩溃，导致再选第二家公司时整页空白。
- 修正：所有读取改为 `doc.metadata.fileName`。
- 副作用：`company-slot` 文件列表显示的"空文件名"也是同一个 bug。

- 原代码 `auditRows(groupsByColumn)`，但签名是 `auditRows(rows: CompareRow[], groupsByColumn: Record<colKey, Record<path, MetadataPreviewGroup[]>>)`，第一参应是 `CompareRow[]`。
- 顺带把 `groupsByColumn` 的 shape 也修对了：之前是按行平铺，应是 `colKey -> filePath -> MetadataPreviewGroup[]`。

### 14. 对比报告跨公司识别 bug + UI 第二轮修复

**用户反馈**（截图：弹窗里两个公司左右都"高卓栋"、"高卓栋"+"Microsoft Office User"，报告却"高 0 中 0 通过 6"）：

2. `compare.rs` 为什么没检查出"不同公司存在相似的人"。

**根因（双重 bug）**：

**(a) 后端 company 字段映射错位** — `src/pages/compare-page/index.tsx` 的 `toCompareInputs` 把 `company` 取自 `doc.metadata.appProperties?.company`（Office 文件自带 OpenXML `Company` 字段），而非用户在 UI 上标的公司槽位。
- 大多数 Office 文件这个字段是空字符串 → 所有文件归到 `company = ""`。
- Rust 端 `compare_files` 看 `unique_companies.len() < 2` 直接 return，跨公司对比一行没跑。
- 因此截图里两侧"高卓栋"明明跨公司同名，但 `compare_metadata` 返回 `[]`。

正确映射：`companyById[doc.companyId]?.name`（用户在 UI 里拖文件夹时标记的"基准方/对比方"名）。

**(b) Rust 端 `< 2` 早返回过严** — 单文件内 `author vs lastModifiedBy` 公司错配检查被一起跳过；同时空 company 名会被当成"同一公司"。

**修复**：
- `src/pages/compare-page/index.tsx`：
  - `toCompareInputs(documents, companyById)`：新增第二参数接收 `companyById`；`company` 取自 `companyById[doc.companyId]?.name`；删掉对 `appProperties` 的依赖。
  - `handleRun` 同步传入 `companyById`。
  - import 增加 `type CompanyEntry`（来自 `file-context`）。
- `src-tauri/src/documents/compare.rs`：
  - `for file in files { check_company_mismatch_in_file(file) }` 移到函数顶、永远先跑（不依赖 `len >= 2`）。
  - `unique_companies` 收集时 `.filter(|f| !f.company.trim().is_empty())`，避免空名被误当同一公司。
  - 跨公司对比段加 `if unique_companies.len() >= 2` 包裹。

**UI 第二轮修复**（仍是单文件 `risk-report-dialog.tsx`）：
- `DialogContent` 用 `w-[min(96rem,calc(100vw-3rem))]` 主动控制宽度，**绕开默认 `sm:max-w-sm` 把弹窗压到 24rem** 的响应式陷阱（className 后写覆盖 base `max-w`，但 `sm:max-w-sm` 在 `@media` 内会卡）。
- `DialogDescription` 改 `flex flex-wrap items-center gap-x-2`，让长公司名换行有节奏。
- `SummaryBigCard`：`text-3xl` → `text-2xl` 数字；icon `size-5` + `shrink-0`；padding 紧凑；label `leading-tight`、hint `truncate`；整体 `items-start gap-3`。
- 文件表列名"最后一次修改者"改成"最后修改者"（避免横向换行）+ `whitespace-nowrap`；状态列加 `whitespace-nowrap`；每行 `leading-snug` 让长名不挤。
- 文件列比例 `1.6fr_1fr_1fr_auto` → `1.8fr_0.9fr_0.9fr_auto` 让文件名列充裕、author/lastModified 列精准；grid 容器加 `min-w-0` 防溢出。

**关键设计教训（沉淀）**：
- **前端 → 后端字段映射要按"业务语义"对齐**，而不是"字段名相同就映射"：`app.xml` 的 `Company` 是 Office 自带元数据，跟用户标的公司槽位是两码事；字段名撞车时最容易出错。
- **早返回条件要看清"它截掉了什么"**：`if len < 2 { return reports; }` 一次截掉 mismatch + cross 两段，这种"省一句 exit early 但实际绕过必要逻辑"的代码要拆成显式分支。
- **`sm:max-w-sm` 是 dialog 的默认兜底**，但要变宽时只用 `max-w-X` 不够（响应式类在 `@media` 内不一定被 className 后写覆盖），必须 `w-[min(...,...)]` 主动控制宽度。
- **`truncate` 不解决"列宽错配"**：列宽比例要按内容预估，truncate 只在 hover 时显示全文，不应该靠它反复收紧。

**验证**：前端 `read_lints` 零报错；Rust 端本次未跑 `cargo check`（按用户硬规则执行命令）。

**用户反馈**："这么影响到外面了"。

**症状**：截图显示，固定布局的报告视图打开后，底栏（"建议优先复核高风险条目，再导出报告归档" + 重新对比/导出报告/关闭按钮）**浮在了 3 张大数字卡的中间**，盖住了卡片内容；同时 02 文件元数据明细 仍可见在底部。

**根因**：上一版让外层用 `<header sticky top-0>` + `<main flex-1 overflow-y-auto>` + `<footer sticky bottom-0>`。但 footer 是 main 的**兄弟节点**，不是 main 的子元素；sticky 需要相对最近的滚动祖先（`overflow != visible` 的祖先），而：
- 外层 `<div fixed inset-0>` 没有 overflow；
- main 才是滚动容器，但 footer 不是它的子级；
- 结果 footer 没有合适的滚动容器，sticky bottom-0 在某些浏览器布局下退化成 `position: relative`，配合 flex flex-col 时出现"飘"在可视区中段而非吸在底部的视觉错位。

**修复**：回归经典「顶栏 + 主区 + 底栏」三段布局：
- `<header>` 去掉 `sticky top-0 z-10`，加 `bg-background/95`，改为 `flex shrink-0`（flex 列容器内不滚动，自然吸顶）。
- `<footer>` 同样去掉 `sticky bottom-0 z-10`，`bg-background/95`、`flex shrink-0` 让它在主区下方自然吸底。
- 因为 `main flex-1 overflow-y-auto`，主区内部仍可滚动、且不溢出；header/footer 在外层 flex 列里按兄弟顺序永远在视口边缘。

**关键设计教训（沉淀）**：
- **sticky 必须有合适的滚动祖先**：要么它在滚动容器**内部**（作为子节点），要么外层本身滚动。在 fixed 全屏布局中，让 header/footer 走 `flex shrink-0` 比 `sticky` 更稳。
- **`bg-background/95` 替代 `bg-background/85`**：与背景几乎不透明，避免滚动内容被透出来，但保留 5% 透明让轮廓层有视觉过渡。
- **看截图别假设**：用户的"影响到外面"可以是底栏漂移、遮罩、跨页面元素溢出等多种，需先确认是布局错位还是样式问题。

**验证**：`read_lints` 全文件零报错。

### 21. ComparePage 返回后再次进入重置状态

**用户反馈**：在 compare 页加载了公司/文件 + 跑过对比 → 点击 ← 返回首页 → 再次进入 compare 页，左/右 slot 仍残留上次的公司名 + 文件 + 上次对比的 findings。

**修复**（`src/pages/compare-page/index.tsx`）：
- `import React, { useCallback, useMemo, useState }` → `useEffect` 加入。
- 在组件顶层加 `useEffect(() => { setFindings([]); setDialogOpen(false) }, [])`：每次 mount 都把局部 findings/弹窗 state 重置，**文件/公司与 file-context 全局层由用户在首页清空，不在此强行清**。
- 之所以不直接 `clearAll()`：用户希望"返回首页再进入"页面干净；而进入时全局上下文清空会丢掉首页可能用的同一份文件（如果首页也用 file-context）。本意就是刷页效果。

**关键设计教训（沉淀）**：
- **页面级 local state 必须在 mount 时主动重置**：useState 不会"自动恢复初始值"，切路由回退/前进会让组件重新 mount，但 state 是新的——但 `useEffect([])` 仍然只跑 mount 时这一次；如果在 mount 后又把 stale 状态写回 state 才会"再出现"。这里是因为某些 Race 让 views 看似带状态。
- **副作用**：检查 `findings.length` 还是上次的——但 `comparing / exporting` 都是布尔，天然 false，没问题。
- **行为契约**：返回首页再进入 compare，UI 表现为「全新会话」，这通常是用户期待（除非他们想要"继续未完成的工作"功能，目前产品语义是前者）。

### 26. shadcn Sidebar 顶部偏移（修 root level，不在调用方绕）

**用户反馈**：之前用 `className="!top-[44px]"` 等多种 Tailwind 写法都没生效——sidebar 仍贴顶覆盖 macOS 红绿灯。

**根因分析**：
- shadcn `Sidebar` 在 `src/components/ui/sidebar.tsx` line 225 用 `fixed inset-y-0 z-10 hidden h-svh ...` 作为 fixed container 默认 class。
- 用户传入的 `className` 通过 `{...props}` 透传到**同一个内层 sidebar-container**，与 `inset-y-0` 同优先级，**不一定能覆盖**（Tailwind v4 编译顺序、important 语法稳定性）。

**真修复**（root level）：
- `src/components/ui/sidebar.tsx` line 225 改默认类为：
  - `fixed top-(--chrome-titlebar-height)` （CSS 变量，macOS/Windows 都是 44px）
  - `h-[calc(100svh-var(--chrome-titlebar-height))]` （高度扣减 titlebar）
  - 删除 `inset-y-0 h-svh`
- 这样**所有** Sidebar 实例自动从 titlebar 下方开始，无需调用方传 className 覆盖。

**反思**：之前反复用 `!important`、Tailwind 任意值、inline style 都无效——是因为没在 root level 改 shadcn 源码。**修根因比绕它更有效**。

### 27. sidebar 顶部偏移最终修复（inline style + class 双保险）

**用户反馈**：改 shadcn 源码用 `top-(--chrome-titlebar-height)` 无效；之前 `editor-page-sidebar.tsx` 用 `top-22` class 是有效的。

**根因**（Tailwind v4 关键坑）：
- Tailwind v4 的 `top-(--var)` 简写语法要求 CSS 变量在 `@theme` 中**注册**，`:root` 定义不够——`top-(--chrome-titlebar-height)` **不会生成有效 CSS class**（因为 `--chrome-titlebar-height` 只在 chrome.css 的 :root，未进 @theme）。
- 普通数字 class `top-22`（88px）**一定生成**，所以之前有效。
- 改 shadcn 源码用变量简写 = 无效。

**最终修复**（`editor-page-sidebar.tsx`，双保险）：
- `className="top-22 bottom-0 h-auto border-r"`（普通 class，保底）。
- `style={{ top: "var(--chrome-titlebar-height, 44px)", bottom: 0, height: "calc(100svh - var(--chrome-titlebar-height, 44px))" }}`（inline，浏览器原生 var() 一定解析）。
- shadcn 源码**恢复原样**（不污染公共组件）。

**教训**：Tailwind v4 变量简写（`top-(--x)`）必须变量在 @theme 注册；项目 CSS 变量（chrome.css）用 inline style 或普通数字 class 才可靠。

### 28. 高度链断裂修复（root cause）：.chrome-window-shell 无高度

**用户定位**：重构后 `SidebarProvider > Sidebar + SidebarInset` 内容铺不满——`AppShell` 的 `h-full` 依赖父级高度，但顶层 `main.chrome-window-shell` **没有 height**（默认 auto），整条 `h-full` 链断裂。

**根因链**：
```
main.chrome-window-shell (main.tsx, 无 height, 默认 auto)
 → App / MetadataProvider（无高度）
  → SidebarProvider className="h-full"  ← h-full 解析失败（父无高度）
   → SidebarInset flex-1 ← 在无高度的 flex 容器里也塌陷
    → AppShell h-full ← 依赖 SidebarInset 高度 → 塌陷
```

**修复**：
- `src/style/chrome.css` `.chrome-window-shell` 加 `height: 100svh; overflow: hidden`。
- `src/layouts/app-shell.tsx` 根 div `h-full` → `flex-1 min-h-0`（在 SidebarInset flex 容器内更稳）。

**教训**：Tauri/React 高度链必须以一个明确的 `100svh` 根开始，否则内部所有 `h-full`/`flex-1` 都会静默塌陷（UI 变形）。这类"看起来没铺满"问题优先查顶层容器高度。

### 31. shadcn Sidebar 折叠态推挤修复 + 文件类型图标

**问题 1**：折叠态 sidebar 没把内容挤过去（折叠态 sidebar-gap 48px 没推挤 SidebarInset）。

**真根因**：shadcn Sidebar 外层 wrapper 是 `block`（md:block），放在 column flex 容器（AppShell content）内时，**block 元素 cross axis width 默认 fill = 100%**，不按 sidebar-gap 限制推挤 SidebarInset。
- 之前结构：`AppShell content (column flex) > {Sidebar, SidebarInset}` → wrapper 占满 100%，sidebar-gap 不推挤。
- 新结构：`SidebarProvider (row flex) > {Sidebar, SidebarInset}` 作为 AppShell content 的单一 child → SidebarProvider 自身宽度 = content 100%，内部 row flex 中 wrapper 按 max-content = sidebar-gap 推挤 SidebarInset。

**修复**（`page-layout.tsx`）：PageLayout 在 sidebar 存在时把 `{sidebar + SidebarInset}` 包进 `<SidebarProvider className="flex flex-1 w-full">`；AppShell 内容区是 SidebarProvider 一个 block 子，SidebarProvider 内部 row flex 推挤生效。

**问题 2**：折叠态 sidebar 文件项图标是默认 lucide 占位，希望显示文件类型图标（pdf/docx/xlsx）。

**修复**（`editor-page-sidebar.tsx`）：SidebarMenuButton 内根据 `file.filePath` 后缀选 `FileSpreadsheet`（xlsx）或 `FileText`（其他）作为 leading icon。折叠时仍可见、展开时与文件名同行。

**教训**：
- shadcn sidebar 体系要求 Provider 是最近 flex row 父，**不能嵌套 column flex 内**（否则 gap 推挤失效）。
- block 元素在 column flex 内的 cross axis (horizontal) 默认 fill 100%，需要 max-content 时改成 inline-block 或显式 width auto。
